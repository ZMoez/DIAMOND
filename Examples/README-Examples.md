## Example 1: Stepper

We introduce a simple system referred to as the *Stepper*.  
This system models a single component that maintains an internal integer variable `x`,  
which it updates periodically based on simple transition rules.  
The Stepper operates in an infinite loop, performing one transition per cycle.

The core behavior of the Stepper is as follows:

- **Initially**, the internal variable `x` is set to `0`.
- **On each cycle**:
  - If `x < 6`, the component proceeds as follows:
    - If `x == 3`, it makes a nondeterministic decision: with equal likelihood, it either resets `x` to `0` or increments it by `1`.
    - For all other values less than `6`, it simply increments `x` by `1`.
  - If `x >= 6`, the component resets `x` back to `0`.
- After each step, the cycle repeats indefinitely.


### Example: Shielded Stepper

In this version, we apply a **shield** to the Stepper model to prevent the system from entering unsafe states.  
Specifically, the system must never allow `x == 5`, which is defined as a safety violation.

<!--  The shield uses the **colored state space** generated by DIAMOND to identify transitions that may lead to unsafe configurations.  
It intercepts such transitions and redirects them toward safe alternatives, ensuring the safety property `□(x ≠ 5)` is always maintained. -->

> **Note**: This model ensures the safety property `x ≠ 5` holds across all execution paths.  
This example demonstrates **preventive runtime safety enforcement** by integrating a shield into the model.


### Example: Stepper-v2 

We extend the original *Stepper* model by introducing an additional nondeterministic choice.  
This variation modifies the transition behavior when the internal variable `x` reaches `4`.

The updated behavior of the Stepper is as follows:

- **Initially**, the internal variable `x` is set to `0`.
- **On each cycle**:
  - If `x < 6`, the component proceeds as follows:
    - If `x == 3`, it makes a nondeterministic decision:  
      with equal likelihood, it either resets `x` to `0` or increments it by `1`.
    - **New behavior**: If `x == 4`, it makes a nondeterministic choice to set `x` to either `5` or `6`.
    - For all other values less than `6`, it simply increments `x` by `1`.
  - If `x >= 6`, the component resets `x` back to `0`.
- After each step, the cycle repeats indefinitely.

> **Note**: This variation introduces different reachable states compared to the original Stepper model, when we want to avoid unsafe state (`x == 5`), due to the nondeterministic jump from `x == 4` to `x == 6`.


## Example 2: LaneChanger (Collision-Aware Multi-Agent System)

In this example, we model a two-lane road scenario with two autonomous cars navigating a finite-length track (`positions 0` to `max_bound`).  
Each car can execute one of five possible actions:

- `0: turn left` (switch lane left)
- `1: idle` (no movement)
- `2: turn right` (switch lane right)
- `3: faster` (move forward)
- `4: slower` (move backward)

#### Constructor Parameters: `riskAverse` and `shielded`

Each car is instantiated with two important behavioral parameters:

- `riskAverse` (`true/false`):  
  - If `true`, the car only selects from the actions (`faster` or `slower`).
  
  - If `false`, the car chooses actions nondeterministically from all five possibilities.

- `shielded` (`true/false`):  
  - If `true`, the car uses a **Shield** (local or central) to validate its action before execution.
  - If `false`, the car executes its chosen action directly without a safety check.

These parameters allow modeling different behavioral profiles, cautious agents, unshielded agents, or fully protected cars.


> We have two local and central version, described below. In both versions, the system enforces a safety invariant:
G !(car0.pos == car1.pos && car0.lane == car1.lane)



### Local Shield (Decentralized)

Each car has **its own internal shield logic**, implemented as a message server (`msgsrv shield()`) in the car's reactive class.  
This decentralized shield has **limited knowledge**, it only sees the other car’s last known state (position and lane) and makes localized safety decisions.

Note that each car shares its current **position and lane** with the other car via a message (`update()`),  
allowing decentralized shields to make decisions based on the **most recent visible state** of nearby agents.

**Behavior:**

1. The car selects an action based on `riskAverse`.
2. If `shielded`, it runs the internal `shield()` method:
   - If the move may result in collision, the shield forces the car to stay idle. 
   - Otherwise, the car proceeds with the intended action.
3. The action is executed via `step()` and the other car is updated.

Demonstrates lightweight **agent-level autonomy with local safety enforcement**.

### Global Shield (Centralized)

In the **centralized version**, cars query a dedicated **Shield reactive class** that has **global knowledge** of all vehicles' current positions and lanes.

**Behavior:**

1. Each car (modeled by `FreeVehicle`) selects an action.
2. If `shielded`, it calls the `Shield.step()` from `reactiveclass Shield` :
   - The Shield checks whether the action is unsafe (e.g., would result in collision).
   - If so, it substitutes the action with `idle` before allowing execution.
3. After stepping, the car reports its updated state back to the Shield via `update()`.

Demonstrates **centralized coordination** and enforcement across multiple agents with **global visibility**.



## Example 3: SimpleCar and SimpleCar-Shielded

This example models an **autonomous car** moving along a bounded road.  
At each cycle, the car chooses one of three actions:  
- `Idle` (do nothing)  
- `Forward` (move toward destination)  
- `Backward` (move away from destination)

#### SimpleCar
The basic version executes the chosen action **without any safety checks**, which may result in:
- Going out of bounds
- Staying idle before reaching destination
- Moving backward/forward unnecessarily

#### ShieldedSimpleCar
The shielded variant wraps each decision with a **simple internal shield** that should:
- Prevents unsafe moves (e.g., out-of-bounds)
- Replaces them with e.g., `Idle` when necessary

> This exampple is not yet complete. 
> This example is an initial attempt to introduce a **shield template** embedded in the actor model, making it a useful starting point for shielding logic in Rebeca models.
